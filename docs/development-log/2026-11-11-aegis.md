### 2. Duplicate telemetry semantics investigated

- Inspected the brute-force duplicate-event test and its relationship to ingestion idempotency.
- The test data contained five duplicate rows that met the brute-force detector's attempt-count threshold.
- The distinction identified was that detector evaluation may count persisted event rows, while ingestion may deduplicate repeated telemetry before detection.
- Related integration tests referenced deduplication/idempotency.
- This was an investigation, not a completed change to duplicate handling. The exact end-to-end semantics still need to be reconciled by comparing the ingestion fingerprint/idempotency path with detector inputs.
- No unsupported conclusion was made that duplicates are either always counted or always removed in every ingestion path.
